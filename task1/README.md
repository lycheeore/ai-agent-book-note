## 打卡要求：Context、Memory、RAG 三者关系

**Context 是唯一的出口，Memory 和 RAG 都是入口。**

- 模型永远只看得到 Context。Memory 和 RAG 的差别不在「模型怎么用」，而在**知识从哪来**——一个来自与用户的交互历史，一个来自外部语料。
- **Memory 是「用户尺度的 RAG」，RAG 是「集体尺度的 Memory」**：两者共用向量检索与知识压缩，也共用同样的麻烦——信息冲突、知识过期、检索不准。
- **Context 管「表达」，Memory / RAG 管「沉淀」**：前者在有限窗口内更聪明地表达信息，后者在窗口之外更可靠地沉淀信息。

一句话：**Context 是工作台，Memory 是档案柜，RAG 是图书馆的检索台。**

## 知识脉络

三章是一条线，不是三个话题：

```
Chapter 1  Agent = LLM + 上下文 + 工具
           └─ 上下文 = 静态前缀 + 轨迹；消融证明各组件并不等价
                    ↓  把「上下文」拆开，做成一门工程
Chapter 2  这一次任务里，模型该看到什么
           └─ 静态前缀受 KV Cache 约束；轨迹膨胀靠压缩与隔离
                    ↓  把「一次任务」放大到「跨任务」
Chapter 3  跨会话之后，还该记住什么、查什么
           └─ 轨迹沉淀为长期记忆；外部知识走 RAG；先立三层次评估标尺
```

具体到概念的承接关系，见[学习记录第 5 节](学习记录/学习记录.md#5-前后知识是怎么接上的本次最大的收获)。
